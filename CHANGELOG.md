### 0.1.0 / 2026-11-24

The first release of the engine: an SCXML statechart interpreter, a conformant sibling of the Elixir `statifier` package, driven as a value step (`compile`, `Machine::start`, `State::step`, `State::advance`) with every effect answered as plain data for the host to carry out. It needs Rust 1.85 or newer and has one runtime dependency, `predicator-rs` 0.1 (0.1.0 at this release), whose compiled conditions, values and scripts it runs. Two features, both off by default: `serde`, which adds `Serialize` and `Deserialize` for a position, an effect and a stopped chart's answer, and `basichttp`, which adds the `basichttp` module, the seam a host fills to carry a Basic HTTP send; the crate ships no HTTP client and no transport. The chart semantics are those of the reference at its `v2.16.0` conformance corpus, vendored under `conformance/`; `conformance/registry.json` claims 320 cases: 119 of `scion`, 36 of `statifier`, 152 of `w3c-mandatory` and 13 of `w3c-optional`, with no case skipped. The public surface is listed in `tests/public-items.txt`, which the full gate compares with the built documentation.

**Added**

- `Value` is re-exported from the `predicator-rs` crate as the value type of a chart's datamodel; it is that crate's own type, so a move to a new minor version of `predicator-rs` is a new minor version of this crate.
- `Effect`, the plain-data effects interpreting answers, starts with `Effect::Log` (a `<log>`'s label and value) and `Effect::DatamodelChange` (a datamodel write's resolved path, source, new and prior values), each carrying the macrostep, microstep and round counters; `BlockOwner` names the block an effect came from and `PathSegment` one segment of a resolved location.
- `Effect::Send`, `Effect::SendDelayed` and `Effect::Cancel`: a `<send>` answers the message it sends (its event, target, type, data and send id, a delayed one with its delay in milliseconds) for the host to deliver, the internal queue included, and a `<cancel>` answers the send id it cancels; each carries its ordinal from the session's timer counter where the reference stamps one, and a send refused for its type or its target raises `error.execution` or `error.communication` carrying its send id instead.
- `State::active_leaf_count` and `Done::active_leaf_count` count the active leaf states, a state with no id counted too, so a caller can tell when `active_leaf_states`, which leaves such a state out, has left one out; with the `serde` feature a `Done` carries the count as `activeLeafCount`.
- `Machine::start(options)` starts a chart in execution and answers a `Moved`: the new `State` and the effects the start produced. `Options` carries the session id, starting datamodel values, the send types the host delivers itself, the `RoundBudget` and the trace flag.
- `State::step(name, data)` sends the chart one external event, and `State::advance(ms)` moves its virtual clock, firing every pending timer due by then; each answers a new state and its effects and leaves the state it was given unchanged.
- `State::configuration()`, `State::done()`, `State::now_ms()` and `State::next_due_ms()` read the active state ids, the stopped chart's donedata and final configuration, the virtual clock and the earliest pending timer.
- `Error`, the refusal of a driver call: `NotRunning`, `InvalidDuration` and `BuiltInSendTypes`.
- `Map` and `Key`, the predicator crate's map and key types, are re-exported beside `Value`.
- `State::export_position` answers a chart's `Position` in the reference's string-id vocabulary: the configuration, the entered states, the states to invoke, the history values, the active invocations, the counters, the datamodel, the running flag and status, the trace flag and the round budget; it refuses with `ExportError` a state whose internal queue holds an event or that holds a state with no id.
- `Machine::import_position` reads a `Position` back into a `State` on any machine that holds every state it names, the virtual clock at 0 and nothing pending; it refuses with `ImportError` an unknown state id (naming every one), a datamodel with no `_sessionid` string, a history value the chart cannot restore and two invocations of one `<invoke>`.
- The `serde` feature, off by default, implements `Serialize` and `Deserialize` for `Position`, `Effect`, `Done` and the types they reach; a position's JSON form has the TypeScript sibling's keys.
- `State::active_leaf_states()` reads the ids of the active leaf states, sorted, the set a conformance case's expected configuration names; a stopped chart answers none, as it has no active state.
- `Done::active_leaf_states` carries the ids of the leaf states of the configuration a chart stopped in, sorted, the set a conformance case's expected configuration names once the chart has stopped; `State::active_leaf_states` answers none on a stopped chart, as the reference's does.
- `ActiveInvocation::new(state, invoke_index, invoke_id)` builds a live invocation for a position a host keeps in its own storage.
- `Position` implements `Default`: the empty position, which a host fills field by field from its own storage and passes to `Machine::import_position`, with or without the `serde` feature.
- `Machine::check_accepts`, which compares a declaration of the event names a chart accepts with the chart's event vocabulary, every descriptor on a transition whose source state some path enters, under the matching transition selection uses. It answers an `AcceptsCheck`: `unreachable`, the declared names no descriptor matches, in the declaration's order and each once; and `undeclared`, the descriptors no declared name matches, as written and in transition order. `None` is no declaration and answers both lists empty; an empty declaration leaves every descriptor undeclared. It refuses nothing.
- `State::report_send_failed`, which reports a send of a registered type the host could not deliver: the sending session takes `error.communication` as a platform event, its `sendid` the send's id whether the document named the send or not, and runs to a stable configuration within the call. A child's send is reported through the `Effect::Child` that carried it. The reason a host passes is written into no field of the event.
- `Error::Halted`, answered by a report while a spent round budget has halted the sending session, and `Error::NotAHandedSend`, answered for an effect that is not a send of a registered type handed to the host.
- `<invoke>` runs: an invocation of the SCXML type whose `<content>` is inline markup starts an in-process child session, its session id its parent's, a dot and the invoke id, inheriting its parent's registered send types; the child's effects are answered among the call's as `Effect::Child`, naming its session id. A child and its parent exchange events through `#_parent` and `#_` and the invoke id, its timers fire through its parent's `State::advance`, it returns `done.invoke.` and the invoke id with its donedata when it stops, and the exit of the invoking state cancels it.
- `Effect::Invoke`, `Effect::CancelInvoke`, `Effect::Autoforward` and `Effect::Child`, and `BlockOwner::Invoke`, the owner of an `<invoke>`'s `idlocation` write; with the `serde` feature each serializes with its own `kind`.
- `<finalize>` runs on an event from its invocation before the parent's selection; an empty one writes the returned values to its `namelist` and `<param location>` entries. An `autoforward` invocation is handed each external event its parent takes.
- `ImportError::UnknownInvoke`: `Machine::import_position` refuses a live invocation naming an `<invoke>` its state does not hold.
- `compile(source)` reads an SCXML document into an immutable `Machine`, compiling every expression through the `predicator-rs` crate, or answers the `Refusal`s of the first stage that refused it, each with a reason, a message and a span; a machine carries the validator's warnings.
- The crate takes its one runtime dependency, `predicator-rs` 0.1.
- The `basichttp` feature, off by default, adds the `basichttp` module: the seam a host fills to carry a Basic HTTP send. It adds no dependency, and the crate ships no transport.
- `basichttp::Transport`, a synchronous trait with one method, `send`, that takes a `Request` and answers a `Response` or a `TransportError`. A host implements it over an HTTP client it already has.
- `basichttp::Request` (method, address, headers in order, body bytes) and `basichttp::Response` (status, headers, body bytes). Every status the server answered is a response, 2xx or not.
- `basichttp::TransportError`, the one error a transport answers when no response came back, with its cause as `source`.
- `basichttp::register`, which registers the Basic HTTP Event I/O Processor in a host's options under its URI (`basichttp::URI`) and its short form (`basichttp::SHORT_FORM`), with the base address whose `location` each `_ioprocessors` entry names, `/` and the session's id.
- `basichttp::deliver`, which takes a send of the processor's type the driver handed the host, encodes it as the reference encodes it (a form body or a text body, `_scxmleventname`, the same percent-encoding and field order, the `scxml-send-key` dedup header) and hands it to the host's transport, passed per call. It answers `basichttp::Delivery`: delivered on a 2xx response, or missed (`basichttp::Miss`: no target, a status outside 2xx, or a transport error), a miss reported to the chart as `error.communication`.
- `basichttp::decode`, which reads a request a host's front received into a `basichttp::Received`, the name and data of an external event for `State::step`, or refuses it with a `basichttp::DecodeError` naming a method other than `POST`, a part that is not UTF-8 (`basichttp::Part`), or a malformed send key.
- `IoProcessorEntry` and `Options::ioprocessors`, the `_ioprocessors` entry a host supplies for each registered send type: a fixed map, or a base address whose `location` names each session, an invoked child's included.
- `Error::UnregisteredEntries`, answered by `Machine::start` for an entry whose type the options do not register.
- `Options::target_required`, the registered send types a `<send>` must name a target for: a send of one with none is still answered as an effect, and the sending session then takes `error.communication` carrying the send's id once its macrostep is done. `basichttp::register` lists both of the processor's spellings.
- `Effect::DatamodelInit`, `Effect::BudgetExhausted` and `Effect::Done`, the effects of the interpreter loop: the datamodel a chart starts from, before any `<data>` binds; a macrostep that spent its round budget (10000 rounds unless the host sets another through `Options::round_budget`) without reaching a stable configuration, with the configuration, the budget and the events still on the internal queue, the chart still running; and a chart that stopped, with its top-level final's donedata, the error evaluating that donedata raised, and the configuration it stopped in.

**Changed**

- `Owner` is renamed `DefaultTransitionOwner`.
- Every validation, lowering and compile reason variant that carries detail is `#[non_exhaustive]`: match its fields with `..`.
- `Effect::Send` and `Effect::SendDelayed` carry `None` for an event, target or type expression that evaluates to null, as for one not written.
- `basichttp::TransportError` is no longer `#[non_exhaustive]`: its fields are private, as `Refusal`'s and `Warning`'s are, so the attribute changed nothing a caller could do.
- `State::next_due_ms` counts an invoked child's pending timers.
- A state's exit takes it off the states to invoke and cancels its live invocations, so a position exported after the exit names neither.
- A registered send type's `_ioprocessors` entry is the one the host supplies in `Options::ioprocessors`; a type with none still has an empty map.
